# Kivo render service

A pull-based Blender worker. It asks the Kivo Worker API for the next render job
(highest plan priority first), builds the scene in Blender 5.2 LTS from the
validated scene data, renders every frame, encodes H.264 MP4 with ffmpeg,
verifies the file decodes, uploads it, and only then reports completion.

It needs only **outbound** HTTPS to the Kivo Worker, so it runs behind NAT, on a
GPU box, or in any container host. Run as many copies as you want; each claims
one job at a time.

## Run

```bash
docker build -t kivo-renderer services/renderer
```

```bash
docker run --rm -e KIVO_API_URL=https://<your-worker-host> -e KIVO_RENDER_TOKEN=<RENDER_SERVICE_TOKEN> kivo-renderer
```

Without Docker (Python 3.13 and ffmpeg required):

```bash
cd services/renderer && pip install -r requirements.txt && KIVO_API_URL=… KIVO_RENDER_TOKEN=… python -m kivo_renderer.worker
```

## Configuration

| Variable | Default | Meaning |
|---|---|---|
| `KIVO_API_URL` | required | Base URL of the Kivo Worker |
| `KIVO_RENDER_TOKEN` | required | Must equal the Worker's `RENDER_SERVICE_TOKEN` secret |
| `KIVO_WORKER_ID` | hostname-pid | Name shown on render jobs |
| `KIVO_WORK_DIR` | `./work` | Scratch space (frames are deleted after each job) |
| `KIVO_POLL_SECONDS` | `5` | Idle polling interval |
| `KIVO_MAX_PIXELS` | 3840×2160 | Largest frame this worker accepts (lets small workers skip 4K jobs) |
| `KIVO_RENDER_ENGINE` | `cycles` | `cycles` (CPU or GPU) or `eevee` (needs a GPU with EGL) |
| `KIVO_RENDER_DEVICE` | `auto` | `auto` uses a GPU when Cycles finds one, `cpu` forces CPU |
| `KIVO_RENDER_SAMPLES` | by quality | Override Cycles samples |
| `KIVO_RENDER_THREADS` | all cores | Limit CPU threads |

## Safety model

Scenes are data, never code. `manifest.py` re-validates every job (types,
ranges, ids, file names) before Blender starts, and `scene_builder.py` only
maps that data onto fixed operations: import GLB, set transform, evaluate a
Meshy animation curve, aim a camera, set a light. A job that references a model
file that does not exist fails — the worker never substitutes a stand-in mesh.

## Tests

```bash
cd services/renderer && pip install -r requirements-dev.txt && python -m pytest -q
```

`test_sampling.py` checks the Python sampler against the fixture generated by
the TypeScript sampler the browser preview uses, so preview and render agree.
